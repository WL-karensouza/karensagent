# 问答助理面板 · astryx 视觉改造 设计文档

- **日期**：2026-10-29
- **范围**：`frontend/src` 中问答助理相关组件
- **状态**：待批准

---

## 一、意图与背景

karensAgent 投研报告页右侧有一个「Karens 问答助理」面板，当前是固定的满高侧栏
（宽 540px，高 `calc(100vh - 112px)`），视觉上沿用项目原有的暖色系（琥珀强调色 `#D97706`）。

目标是把这块面板的视觉与交互换成 **astryx（facebook/astryx，MIT）** 的设计语言，
做法是**用 Vue 复刻**，不引入 React（方法见 `docs/astryx/08-vue-replication-guide.md`）。

**为什么要改**：现有面板不论有没有对话都占满整个右栏高度（`calc(100vh - 112px)`），
用户还没提问时右侧就是一整片空白。改成「收拢态 / 展开态」两段式后，未对话时只占 240px 高，
真正开始对话才长开。**侧栏宽度全程保持 540px 不变**，报告正文宽度不受任何影响。

**内部逻辑零改动**：Pinia store、后端 API、流式数据流、markdown 渲染全部不碰。

---

## 二、目标 / 非目标 / 反目标

### 目标

1. 面板具备**收拢态（240px）**与**展开态（满高）**两种形态。
2. 视觉完全采用 astryx 的色板、圆角、间距体系。
3. 有历史会话时直接展开；无历史时收拢。
4. 对话内容白底黑字。

### 非目标

- 不改后端、不改 store、不改流式协议。
- 不改报告正文（`.report-main`）的任何视觉。
- 不做深色模式（astryx 原生支持，但 karens 现有体系是单套浅色，本次不引入）。
- 不引入 React、不安装 `@astryxdesign/*` 任何依赖。

### 反目标（这样改就算失败）

- 面板展开/收拢导致报告正文布局抖动或横向跳动。
- 内部逻辑被顺带改动（store 字段、请求参数、渲染流程）。
- 引入新依赖（尤其 React 相关）。
- 样式写死裸 hex 而绕过 token 体系。

---

## 三、约束

| 约束 | 说明 |
|---|---|
| 技术栈 | Vue 3.5 + Vite 8，禁止引入 React |
| 依赖 | 不新增任何 npm 依赖 |
| 现有 token | 项目已有暖色 token 体系（`src/style.css` 的 `:root`），新 token 需并存不覆盖 |
| 尺寸 | 侧栏宽 540px 保持不变；1280px 以下走现有堆叠响应式 |

---

## 四、方案对比

| 方案 | 做法 | 结论 |
|---|---|---|
| A · Vue 项目内嵌 React | 引入 `@vitejs/plugin-react` + 桥接层跑 astryx 组件 | **否决**：双框架并存，包体积与维护成本翻倍 |
| B · 只借设计，Vue 重写 | 读 astryx 源码，把 token / 结构 / 样式翻成 Vue | **采用**：零新增依赖，风格一致 |
| C · 整站迁移 React | 42 个 `.vue` 全重写 | **否决**：违背「内部不动」，工作量不可控 |

**选定 B**。理由：astryx 的价值在设计决策（圆角多大、间距几档、气泡多宽），
这些都能直接落成 CSS 变量；React 实现本身没有不可替代的部分。

## 五、设计细节（已确定）

### 5.1 两种形态

| | 收拢态 | 展开态 |
|---|---|---|
| 触发条件 | 该股票历史消息数 = 0 | 历史消息数 > 0，或用户发出第一条 |
| **宽度** | **540px（不变）** | **540px（不变）** |
| 高度 | `240px` | `calc(100vh - var(--topnav-height,64px) - 48px)` |
| 内容 | 头部 + 问候语 + 输入框，垂直居中 | 头部 + 消息列表（可滚）+ 钉底输入框 |
| 过渡 | 高度过渡 `0.28s ease` | 同左 |

> **「有历史」的判断依据（重要）**：后端 `get_or_create_session` 每次请求都会创建会话
> （`backend/chat_agent/routers/chat.py:31`），所以**绝不能按「session 是否存在」判断**，
> 否则面板会永远展开。唯一可靠的判据是**历史消息条数 > 0**。

### 5.2 视觉规格（astryx 原生值）

| 元素 | 值 | 来源 token |
|---|---|---|
| 面板底 | `#FFFFFF` | `--color-background-surface` |
| 助理消息 | 透明（白底黑字） | `variant="ghost"` |
| 用户气泡 | `rgba(5, 54, 89, 0.1)` | `--color-neutral` |
| 主文字 | `#0A1317` | `--color-text-primary` |
| 次要文字 | `#4E606F` | `--color-text-secondary` |
| 强调色（发送键/焦点） | `#0064E0` | `--color-accent` |
| 悬停层 | `#0536590C` | `--color-overlay-hover` |
| 气泡圆角 | `28px` | `--radius-chat` |
| 气泡内边距 | `12px 16px` | `--spacing-3` / `--spacing-4` |
| 气泡最大宽 | `max(80%, 280px)` | 源码原值 |

### 5.3 消息区分方式

**靠头像位置 + 行方向镜像，不靠底色深浅**（与 astryx `ChatMessage.tsx` 一致）：

- 助理：`flex-direction: row`，头像在左
- 用户：`flex-direction: row-reverse`，头像在右
- 系统消息：居中

这与 karens 现有实现的方向一致，主要改的是**用户气泡从琥珀实心改为淡蓝灰**。

### 5.4 保留的功能

- 思考步骤卡片（`ThinkingStepsCard`），对应 astryx 的 `ChatToolCalls`，仅调样式
- markdown 渲染（`marked`）不改
- 时间戳 / 发送者名称（元信息行）保留
- 自动滚动到底的逻辑不动

### 5.5 砍掉的部分

以下 astryx 模板自带的，karens 用不上，**不复刻**：
推荐问题卡片、分类筛选、`@` 提及、`/` 命令、附件抽屉、语音听写、模式切换菜单。

### 5.6 会话归属守卫（组件内新增，不碰 store）

**问题**：`chatMessages` / `chatSession` 在 Pinia store 里是**全局单份**，
且 `fetchChatSession` 只在成功时覆盖、失败时不清空；而 `AiChatPanel` 只在 `onMounted` 拉一次。
从股票 A 切到 B 时，B 的响应回来前面板拿到的仍是 A 的消息，会按 A 的历史误展开；
B 的接口若失败，则一直显示 A 的对话。

**方案**：在 `AiChatPanel.vue` **组件内部**加一小段守卫状态，**不改 store、不改 api 文件**：

- 新增本地 `ref` 记录「当前展示的消息归属哪只股票」（如 `loadedFor`）。
- `watch` `stockCode` 变化时：立即把面板置回收拢态、不再渲染旧消息。
- 新会话数据回来后，比对 `chatSession.stock_code` 与当前 `stockCode`，
  一致才允许进入展开态；不一致或请求失败一律按「无历史」处理。

**边界**：这只影响「什么时候显示什么」，不改变任何数据流；
store 里的字段、请求参数、流式处理保持原样。

> 此项由使用者确认允许（2026-10-29），作为「内部逻辑零改动」的**唯一例外**，
> 验收第 8 条据此松绑：允许 `AiChatPanel.vue` 内新增本地响应式状态，
> 但 `stores/` 与 `api/` 目录下文件仍然零改动。

## 七、边界情况

| 情况 | 预期行为 |
|---|---|
| 无历史 + 无输入 | 收拢态 240px |
| 有历史消息 | 展开态满高（首屏可见一次 240→满高 的展开动画，属预期） |
| 会话数据加载中 | 先保持收拢，结果回来再决定（不做骨架屏） |
| 收拢态下输入并发送 | 立即展开，消息出现在列表 |
| 流式回答进行中 | 保持展开，思考卡片正常显示 |
| 报告切换股票 | **立即收拢并停止渲染旧消息**（§5.6 守卫），待新数据到达再判断 |
| 切到的股票无历史 | 保持收拢态，不残留上一只股票的内容 |
| 视口 < 1280px | 走现有堆叠布局，收拢态仍为 240px 高 |
| 消息极多 | 列表内部滚动，面板高度不变 |
| 后端会话接口失败 | 按无历史处理，显示收拢态（不阻断页面） |
| 聊过之后想回到收拢态 | **不支持手动收起**，有历史即保持展开（本次不做） |

## 八、验收标准

1. 无会话时面板高度约 240px，问候语与输入框垂直居中。
2. 有会话时面板为满高，消息列表内部滚动，输入框钉底。
3. 用户气泡为淡蓝灰底，助理消息为白底黑字、无边框。
4. 气泡圆角 28px，内边距 12/16px。
5. 发送键与输入框焦点为 `#0064E0`。
6. 收拢 ↔ 展开有平滑高度过渡，报告正文不抖动；**宽度全程恒为 540px**。
7. 切股票时不出现上一只股票的对话残留，且不按其历史误展开。
8. `npm run build` 通过；`npm test` 通过。
9. 内部逻辑零改动：`git diff` 不含 `stores/` / `api/` / `utils/` 下任何文件的实质变更。
   **唯一例外**：`AiChatPanel.vue` 内允许新增本地守卫状态（见 §5.6）。

## 九、留给实施者的判断

### 9.1 已定的次要决策（2026-10-29 确认，无需再问）

- **首屏展开动画**：保留。会话异步加载，打开一只有历史的股票会看到 240px → 满高的展开，
  视为过渡效果，不额外做骨架屏或首帧满高。
- **手动收起**：不做。有历史即保持展开，本次不提供收起按钮。
- **收拢态外壳**：保留「Karens 问答助理」头部；`StockReport.vue` 的 `position: sticky` 保持不变。
- **宽度**：540px 全程不变，只做高度动画，正文宽度不受影响。

### 9.2 留给实施者自行决定

- **字体**：沿用项目现有 `Inter`，不引入 astryx 字体栈（避免额外字体请求）。
- **过渡曲线**：除 `ease` 外的具体曲线可微调，以不抖动为准。
- **图标**：发送键等图标手写 SVG，不安装 `@heroicons/vue`。
- **token 命名**：新增变量统一加 `--ax-` 前缀，避免与现有暖色 token 冲突。
- **思考步骤卡片的具体冷色映射**：在 §5.2 色板内自行取用。
