## 一、背景与动机

上一轮改造只把**配色**换成了 astryx，组件形态仍是原有的一套：一行灰字提示 + 单行输入框 + 蓝色「发送」文字按钮，整块做成 240px 高的贴顶矮卡片。

对照 astryx `ai-chat-landing` 模板，实际差距在**形态本身**：

| 模板 | 上一轮实现 |
|---|---|
| 大标题问候语（35px） | 无 |
| 巨型输入容器（约 200px 高、浅灰托盘套白色内框、悬浮阴影） | 单行 input + 矩形按钮 |
| 工具行（Auto / Settings / 语音） | 无 |
| 圆形箭头发送键 | 矩形「发送」文字按钮 |
| 满屏居中布局 | 240px 贴顶矮卡片 |

本次要做的是**组件形态的整体重构**，不是再调一次颜色。

---

## 二、目标 / 非目标 / 反目标

### 目标

1. 收拢态复刻 `ai-chat-landing` 的布局骨架：大标题问候 + 巨型悬浮输入容器 + 工具行 + 圆形发送键。
2. 收拢态与展开态**高度一致**，切换只换内容，不做高度动画。
3. 所有视觉尺寸按 **0.75 比例**从模板等比缩放（模板内容宽 720px → 我们的栏宽 540px）。
4. 输入框改为多行 textarea，Enter 发送、Shift+Enter 换行。

### 非目标

- 不改 store、SSE 流式逻辑、消息气泡样式、思考步骤卡片。
- 不引入任何新依赖。
- 不做附件上传、@ 提及、语音、模式切换的**功能实现**（这些按钮只做视觉）。

### 反目标（这样算失败）

- 工具按钮做成可点击但点了没反应（要么纯装饰不可点，要么真有功能）。
- 收拢/展开切换时页面布局跳动、报告正文宽度变化。
- 消息区被巨型输入框挤压到不可读。
- 引入第三方图标库或 React 依赖。

---

## 三、约束

| 约束 | 说明 |
|---|---|
| 栏宽 | 540px 保持不变，报告正文宽度零影响 |
| 技术栈 | Vue 3.5，禁止 React / astryx 依赖 |
| 设计 token | 沿用已有 `--ax-*` 前缀，新增项同前缀 |
| 无事件按钮 | 必须 `disabled` 或 `tabindex="-1"` + `aria-hidden`，**不能**只是没绑 handler |
| 内部逻辑 | store / api / SSE / markdown 渲染零改动 |

## 四、讨论中确认的决策

| # | 决策 | 结论 |
|---|---|---|
| 1 | 复刻程度 | **完整形态**（大标题 + 巨型容器 + 工具行 + 圆形发送键） |
| 2 | 「输入框在下方」 | **面板拉满右栏高度**，内容垂直居中偏下，不再用贴顶矮卡片 |
| 3 | 收拢/展开高度关系 | **两者都满高**，只切换内容，无高度动画 |
| 4 | 模板零件取舍 | 砍附件 token 行；保留 `@` / Auto / Settings / 🎤（纯视觉）；圆形发送键真发送 |
| 5 | 尺寸策略 | **等比缩放 0.75**（540 ÷ 720） |
| 6 | 标题文案 | `✨ Hi, Karens` / `关于这支股票有什么可以帮你的吗？` |
| 7 | 展开态输入区 | **紧凑形态**（约 60–80px），工具行保留但字号缩小，大标题消失 |
| 8 | 内容垂直位置 | 视觉**偏下**，不是严格居中 |
| 9 | 输入框交互 | 多行 textarea，Enter 发送、Shift+Enter 换行、最高 5 行 |
| 10 | 原「💬 Karens 问答助理」头部 | **删除**，身份由大标题承担 |
| 11 | 面板边框 | 保留边框，**去掉 hover 变蓝**；输入容器用**悬浮阴影**（elevation low） |

## 五、收拢态规格

```
┌────────────────────────────────────┐
│                                    │
│                                    │
│  ✨ Hi, Karens                      │  13px
│  关于这支股票有什么可以帮你的吗？      │  26px
│                                    │
│  ┌──────────────────────────────┐  │  外层浅灰托盘 21px 圆角 + 阴影
│  │ ┌──────────────────────────┐ │  │
│  │ │ @                        │ │  │  内层白框 12px 圆角
│  │ │ 输入问题，Enter 发送       │ │  │  textarea 63px 起
│  │ │                          │ │  │
│  │ │ ✨Auto⌄ ⚙Settings⌄ 🎤  ⊕ │ │  │  工具行 + 圆形发送键
│  │ └──────────────────────────┘ │  │
│  └──────────────────────────────┘  │
│                                    │
└────────────────────────────────────┘
```

| 元素 | 规格（0.75 缩放后） | 模板原值 |
|---|---|---|
| 小标题 | 13px | 17px |
| 大标题 | 26px，行高 1.26 | 35px，行高 1.26 |
| 外层托盘圆角 | 21px | 28px |
| 外层内边距 | 9px | 12px |
| 内层白框圆角 | 12px | 16px |
| textarea 最小高度 | 63px | 84px |
| 托盘阴影（静止） | `0 1px 1px rgba(0,0,0,.1), 0 2px 8px rgba(0,0,0,.1)` | `--shadow-low` |
| 托盘阴影（聚焦/悬停） | `0 1px 2px rgba(0,0,0,.1), 0 2px 12px rgba(0,0,0,.1)` | `--shadow-med` |

- 面板高度：`calc(100vh - var(--topnav-height,64px) - 193px)`
  - 193 = 面板自然顶部相对 topnav 的偏移 169（main-content padding 40 + report-page padding 32 + 返回按钮约 37 + 标题约 60）+ 底部留白 24
  - 效果：首屏从面板自然出现的位置刚好填到视口底部，**完整可见**
  - 已接受的代价：向下滚动触发 sticky 吸附后，面板顶部变为 `topnav + 24px`，底部会留出约 145px 空白
- 面板配色：白底，保留 1px 边框，**去掉 hover 变蓝与阴影变化**
- 内容组（标题 + 托盘）垂直居中后再向下偏移，视觉重心偏下
- 无「Karens 问答助理」头部

## 六、展开态规格

- 大标题消失，消息列表占满主体并内部滚动
- 输入区压缩，**`@` 行与工具行全部保留**，整体高度约 **110–130px**：
  - 外层内边距 9px → 6px
  - textarea 起始 1 行（约 40px），最高 3 行
  - 工具行字号 → 11px
  - 圆角、阴影、圆形发送键**保持不变**，两态看起来是同一控件的疏密缩放
- 输入区钉在面板底部

两态共用同一个 `ChatComposer` 组件，靠 `density` 属性区分紧凑与舒展。

---

## 七、交互规格

| 行为 | 规则 |
|---|---|
| Enter | 发送 |
| Shift+Enter | 换行 |
| 输入框高度 | 随内容增长，超出上限后内部滚动。收拢态：起始 63px（约 3 行），最高 **5 行**；展开态：起始 1 行，最高 **3 行**。两态通过 `maxRows` prop 分档 |
| `@` 图标 | 纯视觉，`aria-hidden`，不可聚焦 |
| Auto / Settings / 🎤 | 纯视觉按钮，`disabled` + `aria-hidden`，不可点击 |
| 圆形发送键 | 真发送；`chatAsking` 为真时禁用并降透明度 |
| 收拢态发送首条 | 立即切换到展开态并显示该消息（沿用现有逻辑） |

## 九、边界情况

| 情况 | 预期 |
|---|---|
| 无历史 + 无输入 | 收拢态，标题 + 托盘垂直居中偏下，首屏完整可见 |
| 页面滚动后 | 面板 sticky 吸顶，底部留约 145px 空白（已接受） |
| 有历史 | 展开态，消息列表 + 底部紧凑输入区 |
| 收拢态输入并发送 | 立即转展开态并显示该消息 |
| 输入多行长文本 | 输入框增高至 5 行后内部滚动，不推挤内容 |
| 流式回答中 | 发送键禁用，思考卡片正常 |
| 切股票 | 沿用归属守卫，立即收拢、不残留旧对话 |
| 视口 < 1280px | 走现有堆叠布局，面板宽度 100%，规格不变 |
| 键盘 Tab | 只落在 textarea 与发送键上，装饰按钮不进入焦点链 |

## 十、验收标准

1. 收拢态：`✨ Hi, Karens`（13px）+ 大标题（26px）+ 浅灰托盘内嵌白色输入框，托盘有悬浮阴影。
2. 托盘圆角 21px、内边距 9px、内框圆角 12px。
3. 收拢态与展开态面板高度一致，切换无高度跳变、无正文宽度变化。
4. 输入框为多行，Enter 发送、Shift+Enter 换行；收拢态最高 5 行、展开态最高 3 行，超出内部滚动。
5. 圆形发送键可正常发送；`@`/Auto/Settings/🎤 不可点击、不进入 Tab 焦点链。
6. 面板边框保留但鼠标悬停不再变蓝。
7. 展开态无大标题，`@` 行与工具行保留，输入区整体约 110–130px 并钉底。
8. **首屏（未滚动）就能完整看到面板，含收拢态的输入框与展开态的输入区**，不被视口底边裁切。
9. 消息气泡、思考步骤卡片视觉与之前一致。
10. `npm run build` 通过；`npm test` 除既有失败外全绿。
11. `git diff` 不含 `stores/`、`api/`、`utils/` 下任何文件。

## 十一、留给实施者的判断

- 图标（✨ / @ / ⚙ / 🎤 / 圆形箭头）手写内联 SVG，不装图标库
- 托盘「偏下」的具体偏移量，在 0–40px 区间内调整到视觉舒适
- `density` 属性的具体取值命名
- 工具行在展开态是否显示分隔线
