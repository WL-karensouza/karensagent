# 产品需求文档：AI 前沿新闻资讯智能体

**作者**：王磊
**更新日期**：2026-07-31
**状态**：运行中（持续迭代）

---

## 1. 执行摘要

AI 前沿新闻资讯智能体是 karensAgent 平台的第一个 Agent。每天 09:00 自动检索 AI 领域重大新闻，由大模型生成中文摘要，以飞书卡片推送到群内；同时支持 Web 端一键手动触发。

相比传统"多源爬取 + 关键词过滤"方案，本 Agent 采用 **LLM 驱动**的信息流水线：理解搜索意图 → 搜索引擎全网取数 → AI 总结成可读摘要，信息更精准、阅读成本更低。

## 2. 背景与目标

### 2.1 背景

- 开发者需要持续关注 AI 前沿动态，但资讯碎片化严重，手动浏览成本高
- 需要一个定时、自动、精简的信息聚合推送，不打扰日常工作流

### 2.2 目标

| # | 目标 |
|---|------|
| G1 | 每天自动推送 AI 日报 + 周报到飞书，无需手动操作 |
| G2 | 推送内容是"可读的 AI 摘要"，而非链接罗列 |
| G3 | 搜索失败时能感知并告警，不静默吞错 |

### 2.3 非目标

| # | 内容 | 原因 |
|---|------|------|
| N1 | 多源爬取（GitHub Trending / HN / ArXiv / HuggingFace） | 已下线，统一走搜索引擎取数，覆盖更广 |
| N2 | 关键词管理 / 过滤 | 已废弃，由 LLM 语义理解替代硬匹配 |

## 3. 目标用户

| 角色 | 描述 | 使用场景 |
|------|------|----------|
| **个人开发者 / AI 从业者** | 需要紧跟 AI 前沿动态的技术人员 | 每天早晨在飞书群收到 AI 日报，无需手动浏览多个网站 |

## 4. 核心功能

### 4.1 定时推送

- 每天自动执行（默认 09:00，推送时间通过配置项设置，无前端配置入口）
- 一次推送包含两部分：
  - 📅 **昨日 AI 新闻**（日报）
  - 📊 **近一周 AI 新闻**（周报）

### 4.2 LLM 驱动的信息工作流

三步流水线：

1. **意图理解**：大模型将中文搜索意图转化为英文搜索词，并动态判断时效天数（意图分析失败时回退为原始意图）
2. **全网搜索**：搜索引擎高级搜索，日报精筛 5 条、周报覆盖 10 条，按时效过滤
3. **中文摘要**：大模型整理搜索结果，生成标注发布时间与来源的结构化中文摘要（摘要失败时截断原始结果兜底）

### 4.3 飞书推送与告警

- 飞书交互卡片：蓝色标题栏 + 日报 / 周报 Markdown 正文 + 注脚
- 日报与周报**全部**失败时，推送红色告警卡片，不静默吞错

### 4.4 手动触发

- Web 端"立即抓取 AI 新闻并推送"按钮 → 后台异步执行 → 执行完成后前端自动刷新统计

### 4.5 Web 管理界面

| 页面 | 功能 |
|------|------|
| 仪表盘 | 今日日报 / 周报、近一周报告数、上次推送时间；系统状态表（数据库 / 定时任务 / 搜索服务 / 摘要模型 / 推送目标） |
| 推送历史 | 历史推送记录列表（时间、平台、资讯数、成功 / 失败） |

## 6. 数据与存储

- 每次搜索 + 摘要结果落库保存（`ai_news_reports`）
- 推送记录写入推送历史表（与股票 Agent 共用同一张推送历史表）

## 7. 技术要点（简要）

| 项 | 选择 |
|----|------|
| 信息源 | Tavily 搜索 API（单源，深度搜索） |
| 摘要模型 | DeepSeek（低温度，保证摘要准确） |
| 工作流编排 | LangGraph 三节点线性流水线（理解 → 搜索 → 摘要） |
| 定时任务 | APScheduler，每天 09:00（Asia/Shanghai） |
| 推送 | 飞书机器人 Webhook（交互卡片） |
| 前端交互 | Vue 3 + Pinia，REST 请求 |

## 8. 成功指标

| 指标 | 目标 |
|------|------|
| 每日推送成功率 | ≥ 95%（以推送历史 status 统计） |
| 摘要覆盖 | 日报、周报均成功生成摘要 ≥ 90% |
| 前端页面加载 | 首屏 ≤ 2s |
